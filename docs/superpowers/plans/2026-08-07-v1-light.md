# v1 Light Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the live app from dark prototype-polish to professional: emergency fixes for the QA blockers, the light Polarsteps-inspired theme (spec §9.1), a responsive trip page, profile/My Trips, ownership attribution, scroll-driven storytelling, and the removal of the last hardcoded data.

**Architecture:** No data-layer changes except one embedded join (attribution). All work is in `web/` plus one API cleanup task. QA re-audit is the shipping gate.

**Tech Stack:** unchanged (React 19, react-router 7, Tailwind 4 tokens, recharts, react-map-gl). No new dependencies.

## Global Constraints

- **QA findings are the requirements** for Tasks 1 and 3: `.superpowers/sdd/qa/mobile-report.md` and `desktop-report.md`. A task claiming a finding fixed must reproduce the QA check that found it.
- **Light theme contract (Task 2 defines it, everyone obeys it):** paper ground `--paper: #faf7f2`, card `--card: #ffffff`, ink text `--ink-t: #1f2a2e`, dim `--dim: #5c6b70`, hairline `--hair: rgba(31,42,46,.12)`, accent = survey coral `--coral: #c94f32` (continuity with the route colour), amber demoted to small warm details `--amber: #a8761f`. Buttons: coral fill, **white text** — contrast ≥ 4.5:1 everywhere, verified, because QA just caught 1.22:1 on the main CTA.
- Display face stays Didot; body/UI moves to the system sans stack (`-apple-system, "SF Pro Text", "Segoe UI", Roboto, sans-serif`); Menlo survives **only** for numerals/data via `.data`.
- Soft radius returns: 12px cards, 999px pill buttons. The radius-0 austerity died with the dark theme.
- Map style flips to `mapbox://styles/mapbox/light-v11`; route stays coral.
- **Touch targets ≥ 44×44px** for every interactive element. **No text below 12px** effective. WCAG AA contrast throughout.
- Lint 0, no `eslint-disable`, no `any`; `useAuth` from `lib/auth-context`; nulls render as "—"; all settled precedent holds.
- **Browser-driving QA agents run sequentially, never in parallel** (Chrome emulation contention, learned the hard way).
- Commit per task; plans and docs committed at creation.

### Task 1: Emergency band — ship today, before the theme

**Files:** `web/src/index.css`, `web/src/pages/Landing.tsx`, `web/src/pages/SignIn.tsx`, `web/src/pages/Trip.tsx`, `web/src/components/Placeholder.tsx`, `web/src/main.tsx`

Fixes the four production embarrassments without waiting for the repaint. Still on the dark theme — these are surgical.

- [ ] **Step 1: CTAs get readable text.** The `.eyebrow` class carries `color: var(--faint)` onto filled buttons (QA: 1.22:1 on "START A TRIP" / "SEND LINK"). Everywhere a filled amber button uses `eyebrow`, override with an explicit `text-[var(--amber-ink)]` (Landing CTA, SignIn submit, NewTrip submit, OwnerPanel none-filled — audit with `grep -rn 'bg-\[var(--amber)\]' web/src` and ensure every hit pairs an explicit ink text class **after** any `eyebrow`). Add a defensive rule in `index.css`:

```css
/* eyebrow is a label voice, not a button voice: filled buttons override it */
.eyebrow.on-fill { color: var(--amber-ink); }
```

and use `eyebrow on-fill` on those buttons.

- [ ] **Step 2: Mobile map gets height.** QA blocker: `.mapboxgl-map` computes to 0 when the trip page stacks. In `Trip.tsx`, the right column's map wrapper becomes `className="h-[45vh] shrink-0 lg:h-auto lg:flex-1 lg:min-h-0"`. (A bare `min-h` on the wrapper does NOT work: Mapbox's own `height:100%` child needs a *definite* height to resolve against — the flex-percentage-definiteness quirk, plan bug #9, found in execution.)

- [ ] **Step 3: A real 404.** `Placeholder.tsx` becomes a proper NotFound (keep the filename or rename; update `main.tsx`):

```tsx
import { Link } from 'react-router-dom';

export function NotFound() {
  return (
    <div className="p-10 max-w-xl">
      <p className="eyebrow mb-2">404</p>
      <h1 className="font-display text-3xl mb-4">There's no trail here.</h1>
      <p className="text-[var(--dim)] mb-6">
        The page you're after doesn't exist or has moved.
      </p>
      <Link to="/" className="eyebrow border-b border-[var(--hair)] hover:text-[var(--amber)]">
        Back to the start
      </Link>
    </div>
  );
}
```

Route `*` uses it; the two remaining `Placeholder` usages (if any) die with it. (Soft-404 HTTP status is an SPA limitation — accepted, noted, not in scope.)

- [ ] **Step 4: Tap targets.** The per-day `gpx` buttons (25×16) get `className="eyebrow hover:text-[var(--amber)] min-h-11 min-w-11 inline-flex items-center justify-center -m-2 p-2"` — padding grows the hit area without moving the layout.

- [ ] **Step 5: Gate + ship.** `cd web && npm run lint && npm test && npx tsc -p tsconfig.app.json --noEmit && npm run build` — clean, 17 tests. Commit (`fix(web): QA emergency band — CTA contrast, mobile map, 404, tap targets`), merge to main, push, confirm Netlify deploy, then re-run the two QA probes that found these (evaluate contrast of the landing CTA; mobile-emulate the trip page and measure `.mapboxgl-map` height > 0). Record results.

### Task 6: Storytelling motion

**Files:** `web/src/pages/Landing.tsx`, `web/src/pages/Trip.tsx`, `web/src/components/TripMap.tsx`, `web/src/index.css`

The Polarsteps note: scroll drives the story. Two motions only — restraint is the brand:

- [ ] **Step 1: Landing reveals.** Sections after the hero get `.reveal` (translateY 16px → 0, opacity 0 → 1, 500ms ease-out) via one `IntersectionObserver` hook (`useReveal()` in `web/src/lib/use-reveal.ts` — create, with cleanup). Honour `prefers-reduced-motion` (observer no-ops; content visible).
- [ ] **Step 2: Trip page day-sync.** Scrolling the day list highlights the day under the cursor/viewport on the map: an `IntersectionObserver` over day rows sets `activeDay`; `TripMap` gains `highlightDay?: number | null` — the matching day's line renders wider/full-coral while others drop to 40% opacity (`line-opacity` expression on `['get','day']`). Hovering a day row does the same on desktop. Reduced-motion: highlight still applies (it's state, not motion).
- [ ] **Step 3:** Verify by scrolling in-browser at mobile and desktop sizes; confirm no jank (no long frames in a performance trace), reduced-motion honoured. Gate + commit.
